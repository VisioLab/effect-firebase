# Cyclic references go through Collection Keys

A model cannot hold a `FirestoreSchema.DocumentReference` into a collection built from itself, such as a user's `bestFriend` or a user's reference to one of their own posts. Typing that field needs the collection's type, which contains `typeof User`, while TypeScript is still computing `typeof User` from the class's base expression (TS2310/TS2506). `typeof User` is only safe there when TypeScript reads it lazily, and a collection constant's type can only be inferred from `Collection.make(…, User)`, so it is only safe one step further away: as the member of an interface that nothing opens until the reference is used. We therefore name such a target with a **Collection Key**, `interface UsersKey extends Collection.Key<typeof Users> {}`, and `FirestoreSchema.DocumentReference<X>` accepts either a collection or a key, resolving the key to the same `Collection.DocumentReference<typeof Users>` a collection would give. The cyclic field is written the way Effect writes recursive schemas, with an annotated `Schema.suspend((): FirestoreSchema.DocumentReference<UsersKey> => FirestoreSchema.DocumentReference(Users))`. The body of that function is checked after the class exists, so a key that does not match the collection is a type error.

Acyclic fields keep `FirestoreSchema.DocumentReference(Users)` with no annotation.

## Considered Options

- **A type alias spelling out every level** (`Collection.Collection<readonly [readonly ["users", typeof User], readonly ["posts", typeof Post]]>`). It works today without library changes, but it copies the whole chain of paths and models by hand at every referenced collection.
- **Naming the constant directly**, as `type UsersC = typeof Users` or `interface UsersRef extends FirestoreSchema.DocumentReference<typeof Users> {}`. Both are circular: `Schema.suspend` opens the interface right away, and the constant's type needs `User` finished.
- **A global registry from path strings to collections** through module augmentation, as TanStack Router's `Register` does. Rejected because there is one per program, it adds a second name for every collection that can disagree with the definition, and it needs registration boilerplate apart from the model.
- **A reference typed by path and the target's model** (the typesaurus shape, `ref<Post>("users/posts", …)`). Rejected because the path has to be repeated as an argument, and a self-reference still needs the model's own `typeof`.
- **A marker on the model class pointing to its collection** (`declare readonly "~collection": typeof Users` in the class body). It type-checks, but it ties a model to a single collection, while a model must be able to back several, such as `users` and `archivedUsers`. It also puts a type-only member on every document and makes the model know where it is stored.
- **A collection type that drops its ancestors' models**, so a subcollection's type no longer contains its parent's model. That fixes references from a parent into its own subcollection, but not self-references or mutual cycles, and it is a breaking change to `Collection`'s type parameter.
