`Firestore.make` builds a portable `Firestore` from Effect-native hooks that read and write Firestore Values by document path and `CollectionSelector`, so a backend supplies only those hooks. Core encodes writes through the model, decodes reads into snapshots with any extra a hook hands back, matches Collection Group documents to their collections, names spans, and provides the `Transaction` built from a hook's `TransactionOperations` to the body. The `runTransaction` hook is a `RunTransaction` value holding the function that runs a body over each attempt's operations and an optional `context` that offers the transaction under further tags: the transaction it is handed has a `getDocs` exactly when the operations read many documents. `MakeOptions`, `RunTransaction`, `CollectionSelector`, `TransactionOperations` and the types they read and write are public and unstable.

`Firestore.make` infers the service it builds from its hooks and returns it as a `Firestore.With<ReadOptions, ListenOptions, Extra, TransactionServices>`: its reads and listens take the options the read and listen hooks are handed, its document snapshots, query snapshots and each of their documents carry the extra those hooks hand back, and `runTransaction` asks a body's caller for neither `Transaction` nor the services the transaction hook's `context` offers. `Extra` is inferred from the `getDoc` hook, and the other read and listen hooks must hand back the same, so hooks with mismatched extras do not compile. A `With` whose transactions offer fewer services than another's is not assignable to it, so an SDK's Firestore interface checks that its transaction hook's `context` offers what the interface promises; give each such service a nominal, class-style key, since one whose type extends `Transaction` is dropped from a body's requirements by every `Firestore`. A backend with no options, extras or services builds something assignable to the portable `Firestore`, which is now `With` with every parameter at its default and reads exactly as before. `DocumentRead`, `QueryDocumentRead` and `QueryRead` take the extra as a type argument, with none by default, and their `extra` is required where the extra has fields.

`Firestore.transactionFromCallback` builds the `runTransaction` hook for an SDK that runs a transaction as a callback and retries it, taking the hook's `context` next to `run`, `operations` and `onError`. A body's own failure is never retried and comes back unwrapped, a `FirestoreError` hands its SDK cause back so the SDK retries by its own rules, and interrupting the transaction waits for the SDK to roll back.

`Firestore.streamFromListener` builds a listen hook's stream from an SDK listener that hands back an unsubscribe function: each run attaches a listener and detaches it when it stops, a reader that falls behind sees only the latest snapshot, and a listener error or a snapshot that fails to map fails the stream.
